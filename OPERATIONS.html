Everything is cloud-hosted — there's no home server in the live path. The app runs on Vercel (Next.js 15, auto-deployed from GitHub main); the database and uploaded files live in Supabase; email goes through Resend from the verified openresearchtunisia.org domain. Local development runs fully offline on the same code — the environment picks the backend.

Running it day to day

Everything from the /admin console

Applications
Every project application. Admins can decide when a lead goes quiet.
Posting requests
Approve who may post projects — granting posting rights and the Lead role.
Projects
Approve or reject submitted projects. A new non-admin project stays invisible to the public until approved; rejecting it (with a note) sends it back to its lead to edit and resubmit.
Workshops
Oversee every workshop on the platform.
Members
Change roles, suspend or reinstate accounts, and open anyone's Activity page — sign-in history, full action trail, contributions, applications, enrolments.
Audit log
Every meaningful action across the platform, newest first.
  • Make someone an admin — Members tab → their card → set role to Admin.
  • Suspend an account — Members tab → Suspend. This also ends their live sessions immediately.

Deploying changes

Push to main — nothing else

# Vercel watches main and rebuilds automatically.
git push origin main

The build runs prisma migrate deploy, so new database migrations apply themselves on every deploy — there's no separate database step. A green check in the Vercel dashboard means it's live.

Never commit secrets. .env and env copy are gitignored, and GitHub push protection blocks any push containing a key. Production secrets live only in Vercel → Settings → Environment Variables:
DATABASE_URLDIRECT_URLAUTH_SECRETRESEND_API_KEYEMAIL_FROMSUPABASE_URLSUPABASE_SERVICE_ROLE_KEYSUPABASE_STORAGE_BUCKET

Putting it on openresearchtunisia.org

A real sequence — do it in order

The site currently answers on its *.vercel.app address. To move it to the real domain — no Cloudflare account needed:

  1. Vercel → Project → Settings → Domains → add openresearchtunisia.org and www.openresearchtunisia.org.
  2. Namecheap → Advanced DNS → remove the parking CNAME and any URL-redirect record, then add exactly what Vercel shows: usually an A record @ → 76.76.21.21 and a CNAME www → cname.vercel-dns.com.
  3. Leave the Resend records untouched — resend._domainkey, the send TXT + MX, and _dmarc. HTTPS is issued automatically.

Known limits — read before launch

What to plan around

Important
Uploads over ~4.5 MB fail on Vercel — a hard platform cap on request size. Existing large files (like the intro presentation) serve fine; it only blocks new uploads above the limit. The fix, if it becomes essential, is direct browser-to-Supabase uploads.
Important
Supabase free tier pauses after ~1 week idle — the database sleeps and the site errors until manually resumed. Upgrade to Pro ($25/mo) before public launch, for no-pausing and daily backups.
Note
HTML presentations must be self-contained — all assets embedded, as Manim Slides exports by default. They're served inside a security sandbox.
Note
No rate limiting yet on login or application submission.

When something breaks

Fast paths

  • Someone can't sign in → have them use Forgot password on the login page.
  • Abusive account → Members tab → Suspend (revokes their sessions at once).
  • Bad deploy → Vercel → Deployments → open the last good one → Promote to Production. Instant rollback.
  • Figure out what happened → /admin → Audit log, or a person's Activity page.
